# Keith's Superdeli — F&B Operations App

Unified operations platform for Keith's Superstore deli departments.
Combines Deli Pro inventory management, Food Safety Inspections, and Equipment Cleaning Logs into one store-isolated app.

---

## URL Structure

| URL | What loads |
|-----|-----------|
| `/?store=107` | Store #107 (Saucier) full app |
| `/?store=107&tab=inspection` | Opens directly to inspection form |
| `/?store=107&tab=logs` | Opens directly to cleaning logs |
| `/?view=coordinator` | Chain-wide coordinator dashboard |

---

## Modules

1. **Deli Pro** — Inventory, food cost, invoices, orders, recipes, suppliers, analytics
2. **F.S. Inspection** — 14-section food safety checklist with photo upload, maintenance tickets, PDF export
3. **Cleaning Logs** — Bakery Case, Pretzel Warmer, Tea Bubbler, Frazil Machine, Cafe Tango, Refrigerator Temp, Freezer Temp
4. **Coordinator Dashboard** — Chain-wide inspection status, follow-up alerts, food cost summary

## Setup Instructions

### 1. Create a Google Cloud Project

1. Go to [console.cloud.google.com](https://console.cloud.google.com)
2. Create a new project (e.g. "Keiths Superdeli")
3. Enable the **Google Drive API** and **Google Sheets API**
   - APIs & Services → Library → search each → Enable

### 2. Create a Service Account

1. APIs & Services → Credentials → Create Credentials → Service Account
2. Give it a name (e.g. "superdeli-sa")
3. Skip optional steps, click Done
4. Click the new service account → Keys tab → Add Key → JSON
5. Download the JSON key file

### 3. Share the Drive Folder

1. In Google Drive, open the **Deli Pro — All Stores** folder (or create a new one)
2. Click Share → paste the Service Account email (from the JSON key, field `client_email`)
3. Give it **Editor** access

### 4. Configure the App

**Option A — Local dev (browser opens files directly):**

```bash
cp serviceAccount.example.js serviceAccount.js
# Edit serviceAccount.js and paste your key values
```

**Option B — Vercel deployment:**

Set these environment variables in your Vercel project settings:
- `VITE_SA_KEY` — the full contents of your service account JSON (stringified)
- `VITE_FOLDER_ID` — your Drive folder ID

Note: Because this is a vanilla JS app (no build step), in production the service account is embedded in `serviceAccount.js`. For teams, keep that file out of git (it's in `.gitignore`) and inject it at deploy time using a build script or CI secret.

### 5. Run the Migration

```bash
# Step 1: scaffold config
node setup.js \
  --sa ./your-service-account-key.json \
  --folder YOUR_NEW_DRIVE_FOLDER_ID

# Step 2: copy all 43 stores, add tabs, write stores.js
node migrate.js
```

The migration script will:
- Copy all existing store Sheets from the old folder to your new folder
- Add Inspections, Cleaning Logs, and Temp Log tabs to each Sheet
- Write column headers to each new tab
- Output the store→sheetId map to `stores.js`

If a store doesn't have an existing Sheet it will be copied from the template (`1jtE9hPaF9MIzDuwyJruTTse94XjS-64SR2vNdNoNpKU`).

### 6. Deploy to Vercel

```bash
# Install Vercel CLI if needed
npm i -g vercel

# Deploy
vercel --prod
```

The app is a static site — no build step, no Node server. Vercel serves the files directly.

## Adding Sheet IDs Manually

If you skip the migration, you can manually paste Sheet IDs into `stores.js`:

```js
'107': { name: 'Saucier', sheetId: '1abc...xyz' },
```

Get the Sheet ID from the Google Sheets URL:
`https://docs.google.com/spreadsheets/d/SHEET_ID_HERE/edit`

## Integrating Existing Deli Pro Code

Share your existing Deli Pro source and the `deliProInit()` function in `deliPro.js` will be replaced with the full implementation. The existing Google Sheets service account format (private key as JS array) is already used throughout this app.

---

## Connecting Deli Pro Code

When you share the existing Deli Pro source, paste the relevant code into `deliPro.js` inside the `deliProInit(container, storeNum, storeName, sheetId, serviceAccount)` function. The function receives:
- `container` — the DOM element to render into
- `storeNum` — URL param store number string
- `storeName` — city name from STORES map
- `sheetId` — Google Sheet ID for this store
- `serviceAccount` — the SERVICE_ACCOUNT object from serviceAccount.js

## Google Sheet Tab Structure

Each store's Sheet should have these tabs:

| Tab | Purpose |
|-----|---------|
| `Dashboard` | Existing Deli Pro summary (store name in A1) |
| `Deli Pro` | Existing inventory/food cost data |
| `Inspections` | One row per inspection (written by inspection.js) |
| `Cleaning Logs` | One row per cleaning log entry (written by cleaningLogs.js) |
| `Temp Log` | Reserved for detailed temp log rows |

The migration script creates and headers these tabs automatically.

---

## Inspection Score Calculation

- **Score %** = YES / (YES + NO) × 100 (N/A items excluded from denominator)
- Follow-up date = Inspection date + 7 days
- Any NO on a checklist item opens a photo upload area
- Ice cream machine "working properly" NO opens a maintenance ticket form

---

## PDF Export Notes

All PDF exports use jsPDF loaded from CDN. The app strips all non-Latin characters (including emoji) before passing text to jsPDF to prevent crashes. Only plain ASCII-range characters appear in exported PDFs.
